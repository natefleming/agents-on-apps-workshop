Deployment — Option A

Deploy from Workspace UI

1. Create App

Compute > Apps > Create App. Enter a name and source code path.

2. Add Resources

Click Add Resource for each dependency. The app’s SP gets permissions automatically.

3. Deploy

Upload source code and click Deploy. The UI creates a service principal automatically.

Resources to Add

All chapters need these two:

Experiment MLflow experiment → CAN_MANAGE
Endpoint databricks-claude-sonnet-4-5 → CAN_QUERY

Ch 4 (Memory) also needs:

Database Lakebase → CAN_CONNECT_AND_CREATE
Endpoint databricks-gte-large-en → CAN_QUERY
Deployment — Option B

Deploy from CLI

Three commands to go from local code to a live app. Uses app.yaml for runtime config, resource permissions set in the UI.

# 1. Create the app databricks apps create my-agent # 2. Sync source code to workspace USER=$(databricks current-user me | jq -r .userName) databricks sync . "/Users/$USER/my-agent" # 3. Deploy databricks apps deploy my-agent \ --source-code-path /Workspace/Users/$USER/my-agent # 4. Query (OAuth token required, not PAT) databricks auth token curl -X POST <app-url>/invocations \ -H "Authorization: Bearer <token>" \ -H "Content-Type: application/json" \ -d '{"input": [{"role": "user", "content": "Hello!"}], "stream": true}'

app.yaml

command: ["uv", "run", "start-app"] env: - name: MLFLOW_TRACKING_URI value: "databricks" - name: MLFLOW_EXPERIMENT_ID valueFrom: "experiment" - name: LAKEBASE_INSTANCE_NAME value: "my-lakebase"

After apps create, add resources in UI:

  • MLflow Experiment → CAN_MANAGE
  • Serving Endpoint → CAN_QUERY
  • Lakebase Database → CAN_CONNECT_AND_CREATE
Deployment — Option C

Deploy from Automation Bundles

One databricks.yml declares the app, resources, permissions, and environments. One command deploys everything.

# databricks.yml bundle: name: agents-workshop resources: apps: agent_app: name: workshop-${var.suffix} source_code_path: . config: command: ["uv", "run", "start-app"] env: - name: LAKEBASE_INSTANCE_NAME value: ${var.lakebase} resources: - name: llm serving_endpoint: name: databricks-claude-sonnet-4-5 permission: CAN_QUERY - name: database database: instance_name: ${var.lakebase} permission: CAN_CONNECT_AND_CREATE permissions: - level: CAN_USE group_name: users targets: dev: mode: development default: true prod: mode: production

Deploy Commands

# Validate YAML syntax databricks bundle validate # Deploy to dev (default target) databricks bundle deploy # Deploy to staging or production databricks bundle deploy -t staging databricks bundle deploy -t prod # Run the deployed app databricks bundle run # Check status / tear down databricks bundle summary databricks bundle destroy

What the bundle handles

  • Creates app and grants SP permissions
  • Syncs source code to workspace
  • Multi-target: dev / staging / prod
  • Variables avoid name collisions per user
Deployment — Option D

Deploy from Python SDK

Full app lifecycle in Python via WorkspaceClient().apps. Create, deploy, update, stop, and delete — all programmatically.

from databricks.sdk import WorkspaceClient from databricks.sdk.service.apps import ( App, AppDeployment, AppResource, AppResourceServingEndpoint, EnvVar, ) w = WorkspaceClient() # 1. Create app with resources app = w.apps.create_and_wait(App( name="my-agent", resources=[AppResource( name="llm", serving_endpoint=AppResourceServingEndpoint( name="databricks-claude-sonnet-4-5", permission="CAN_QUERY", ), )], )) # 2. Deploy from workspace path w.apps.deploy_and_wait( "my-agent", AppDeployment( source_code_path="/Workspace/Users/me/agent", env_vars=[EnvVar( name="MLFLOW_TRACKING_URI", value="databricks", )], ), )

Manage the lifecycle

# Check status app = w.apps.get("my-agent") print(app.url, app.app_status.state) # List deployments for d in w.apps.list_deployments("my-agent"): print(d.deployment_id, d.status.state) # Stop / start / delete w.apps.stop_and_wait("my-agent") w.apps.start_and_wait("my-agent") w.apps.delete("my-agent")

When to use SDK

  • CI/CD pipelines with custom logic
  • Deploy from Databricks notebooks
  • Dynamic multi-tenant provisioning
  • Integration testing frameworks
Deployment

App Source: Workspace vs Git Repo

Every app deployment needs a source. Choose a workspace directory for fast iteration, or a git repo for production traceability.

Workspace Directory

Sync local code to the workspace, then deploy from that path.

# CLI databricks sync . "/Users/$USER/my-agent" databricks apps deploy my-agent \ --source-code-path /Workspace/Users/$USER/my-agent # SDK w.apps.deploy(app_name="my-agent", app_deployment=AppDeployment( source_code_path="/Workspace/Users/me/my-agent"))

Git Repository

Deploy directly from a branch, tag, or commit. No sync needed.

# 1. Create app with git repo (one-time) databricks apps create --json '{ "name": "my-agent", "git_repository": { "url": "https://github.com/org/repo", "provider": "gitHub" } }' # 2. Deploy (inherits git_repository from app) # source_code_path is optional (defaults to repo root) databricks apps deploy my-agent --json '{ "git_source": { "branch": "main", "source_code_path": "./apps/my-agent" } }' # Automation Bundles (databricks.yml) resources: apps: my-agent: git_repository: url: https://github.com/org/repo provider: gitHub git_source: branch: main source_code_path: ./apps/my-agent # optional
Git providers: GitHub • GitLab • Azure DevOps • Bitbucket • AWS CodeCommit
Git refs: branch • tag • commit SHA

The Server Contract

@invoke() and @stream()

These decorators register your agent functions with the MLflow AgentServer. It handles the REST API, auth, and tracing.

@invoke() async def non_streaming(request: ResponsesAgentRequest) -> ResponsesAgentResponse: """Called for non-streaming requests.""" outputs = [event.item async for event in streaming(request) if event.type == "response.output_item.done"] return ResponsesAgentResponse(output=outputs) @stream() async def streaming(request: ResponsesAgentRequest) -> AsyncGenerator: """Called for streaming requests. Yields events in real time.""" agent = await init_agent() messages = {"messages": to_chat_completions_input(request.input)} async for event in process_agent_astream_events( agent.astream(input=messages, stream_mode=["updates", "messages"]) ): yield event
Chapter 2

Hello Agent: Custom Tools

Define tools as simple Python functions. The LLM reads the docstring to decide when to call each one.

@tool def get_current_time() -> str: """Get the current date and time.""" return datetime.now().strftime("%Y-%m-%d %H:%M:%S") @tool def calculate(expression: str) -> str: """Evaluate a math expression.""" result = eval(expression, {"__builtins__": {}}, {}) return str(result)
# Create the agent TOOLS = [get_current_time, calculate] MODEL = ChatDatabricks( endpoint="databricks-claude-sonnet-4-5" ) def init_agent(): return create_agent( tools=TOOLS, model=MODEL )

Try it:

  • "What time is it?"
  • "What is 42 * 17?"
  • "Tell me a joke"
Chapter 3

MCP Server Integration

What is MCP?

Model Context Protocol standardizes how agents discover and use tools. Like a USB port for AI tools.

Built-in Databricks MCP Servers

  • system.ai — Python code interpreter
  • sql — Query SQL warehouses
  • vector-search — Search indexes
  • genie — NL data exploration
  • functions — UC Functions

Chapter 4

Short-Term & Long-Term Memory

Add conversation history and persistent user knowledge backed by Lakebase (managed Postgres).

Short-Term

Conversation History

AsyncCheckpointSaver persists messages per thread ID. The agent remembers what was said earlier in the session.

Long-Term

User Knowledge

AsyncDatabricksStore with semantic search. Facts persist across sessions — preferences, role, projects.

from databricks_langchain import ( AsyncCheckpointSaver, AsyncDatabricksStore, ) # Both backed by Lakebase async with AsyncCheckpointSaver( instance_name=LAKEBASE ) as checkpointer: async with AsyncDatabricksStore( instance_name=LAKEBASE, embedding_endpoint="databricks-gte-large-en", embedding_dims=1024, ) as store: agent = await init_agent( checkpointer=checkpointer, store=store, )
